# 个人偏好设置界面 - 前端交互逻辑说明 (PRD)

## 1. 页面模块概述
此页面向用户提供“基本信息（考生成绩）”和“个人偏好”两组模块的填写与修改，旨在全方位描绘考生画像以生成后续的志愿预测评估。
页面结构自上而下分为两大卡片群，辅以顶部导航栏和底部悬浮操作按钮。
整体页面的设计思路为**“局部微观操作”置于各自模块容器内解决，“全局宏观操作”统一步定在底栏汇总执行**。

## 2. 表单与交互逻辑详解

### 2.1 模块一：填写考生成绩 (基本信息)
该模块属于核心输入项，采用高度联动的层级表单：

* **高考省份单选**：
  * **组件与交互**：点击表单唤起从屏幕底端滑出的满宽度抽屉 (Bottom Action Sheet)。抽屉内通过网格列表显示全国省份。
  * **选定反馈**：单选互斥，选中后该网格组件呈主题色高亮边框填充状态，随后抽屉主动收起（带过渡动画），并将所选省名覆写于表单回显区。

* **高考年份单选**：
  * **组件与交互**：操作逻辑与省份相同，唤醒年份抽屉面板（如：2026/2027/2028…）。单项选中之后伴随自动关闭更新原 DOM。

* **成绩类型 (本科 / 专科) - 【联动触发器】**：
  * **组件与交互**：左右双向胶囊式分段开关（Segmented Control），属于基础必填项。
  * **下层表单动态装载逻辑**：
    * 选在「本科」状态：下方表单区展开显示【选考科目】选择栏与【高考总分】填报栏。
    * 选在「专科」状态：下方表单区收缩隐藏【选考科目】，并且数字输入栏的文案与占位会变更为单行的【语数外总分】体系。

* **选考科目组件 (仅「本科」状态出现)**：
  * **组件与交互**：点击唤起科目的多选向抽屉。内置（物理/化学/生物/历史/政治/地理）六大科目胶囊按钮。
  * **强校验机制（限选3门）**：
    * 当选中数 `< 3` 门时，抽屉内【确认】大按钮由于未达标被判定为 `disabled` 不可用置灰。
    * 当选中数 `=== 3` 门时，放开【确认】按钮的高亮及权限。再点击额外的未选科目时，目标按键不会被推入已选数组，而是执行 UI 震动/闪烁提示被阻断。
    * 点击抽屉【确认】完成录入后，将其连词逗号分隔拼接并回填至父级表单内（视觉上变为主强调色避免与Placeholder混淆）。

* **分数段输入**：
  * 右对齐原生数值输入控件，移动端唤起 `type="tel"` 防误触数字小键盘。

### 2.2 模块二：填写个人偏好
采用了基于纯 JS 响应的“页中 Tab 系统”，囊括了四个维度的标签页（院校、专业、地区、更多）。各切页滑动时不重加载全局背景框，利用底纹横线与过渡动画来提升反馈质感。

* **2.2.1 院校 & 专业 Tab**
  * **视图**：主要呈现已预设定心仪的学校/专业列表流。
  * **交互与重构点**：移除了脱节的全局添加按钮。该 Tab 内列表自带独立的内联按钮。若用户初次进来无数据，则以直观巨大的空状态 (Empty State) 直接配发一个带边框的次级交互按钮（`+ 去添加院校`）。

* **2.2.2 地区 Tab**
  * **视图**：无空状态场景，页面装载 (DOMContentLoaded) 时通过代码预演化一个涵盖中国 31 的省 / 自治区 / 直辖市长通列表在面板内。
  * **控制逻辑**：每一个省市条目自身带有一个内联的胶囊开关，控制此省份当前状态处于「考虑」侧还是「不考虑」侧，切换时赋予不同的背景主次高亮反馈。
  * **动态编排逻辑 (SortableJS)**：
    * **拖动意向排序**：用户可在移动端（长按 150ms 以防误触发普通滚动）或 PC 鼠标落键在省份项最左侧的手柄 `grip-lines` 图标处。此时拖拽物发生 `z-index` 脱离和实体投影（`shadow-2xl`），可于省市列表中实施上下拖动，用以界定志愿报考时的先后意向次序。

* **2.2.3 更多 Tab**
  * **视图**：主要为选项配置列表，内容为“民办院校”、“中外合作专业”、“少数民族预科”等。
  * **交互**：右挂单独的小型化胶囊单选块充任（同类“考虑/不考虑”）的配置节点开关。

### 2.3 底部交互与统筹保存系统
屏幕底部配有一个全局悬浮底栏（通过 `bg-gradient-to-t` 设置向上的透明保护蒙版防文本穿模），内藏两个平分布局的巨型触控按钮。

* **取消**：次级白底样式，触发时通常连接舍弃缓存栈数据退回上一页、或抛弃当前页所有的内存变更。

* **确认**：主品牌色亮面加厚重悬浮阴影按钮。它是该偏好流的最终提交闸口。

  * **动效**：点击后自身变更为 `提交中... (Loading Spinner)` 以阻塞重复请求，完毕后吐出成功状态文案复位。
  * **【保存合规校验核心逻辑】**：
    * 尽管两个模块（填写考生成绩、填写个人偏好）在前端视角看似分隔且可各自进行局部子面板开关等操作；其内部逻辑必须在持久化阶段进行【双模块绑定的复合联控联合校验】。
    * **规则**：若此时用户**任一模块**填写出现缺漏、或相互冲突造成了数据合规性崩塌（举例：选了本科且写了分数，但【选考科目】处还未填；或是必填项缺失），程序应拦截【确认保存】放行，拒绝向后端发送此次业务请求。
    * **反馈**：拦截后，表层给出响应性的报错阻拦方案（如：弹窗、红字或直接滑动聚焦异常字段点），只有在两套模块的所有节点逻辑自洽且格式正确时才能视为配置合法。
